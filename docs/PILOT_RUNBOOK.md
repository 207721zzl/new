# EvidenceRAG 试点运行手册

## 1. 试点边界

- 管理员只使用 `/admin`，负责账号、知识库、审计和试点运行看板，不能调用问答接口。
- 普通员工只使用 `/` 进行知识查询和查看自己的会话，不能读取任何管理 API。
- 当前知识库对所有普通员工共享。若部门文档不能互查，必须在扩大试点前增加文档级权限。
- 问题、最近四条对话以及检索命中的父块正文会发送给 DeepSeek。只允许导入已经通过数据负责人确认的资料。

## 2. 每日检查

管理员打开“试点运行”页面，至少确认：

1. 模型状态为“已就绪”，卡住任务为 0。
2. 过去 24 小时问答或入库失败已经查明原因。
3. API 5xx 没有持续增加，磁盘空间充足。
4. 待审批账号及时处理；管理员和员工都使用实名账号。
5. Token 用量、并发量和响应时间没有异常增长。

建议告警线：问答成功率低于 95%、出现卡住任务、API 5xx 超过 1%、磁盘剩余低于 20 GB、P95 超过业务约定值时暂停扩容试点。

## 3. 数据保留与清理

默认保留期：

- 用户会话：90 天。
- 已撤销或到期的登录会话：失效后 30 天。
- 管理审计：365 天。

管理员可以在“试点运行”中先查看清理预览，再执行清理。清理是永久操作，会新增一条审计记录。调整保留期时修改 `.env` 中对应的 `PILOT_*_RETENTION_DAYS`，并在重启前取得备份。

## 4. 备份与恢复

每日执行 MySQL 与上传原件备份：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/backup_pilot.ps1
```

每周或重大入库前执行包含 Milvus、etcd 和 MinIO 的离线快照：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/backup_pilot.ps1 -IncludeVectorVolumes
```

备份目录包含 SHA-256 清单。至少每月在隔离环境做一次恢复演练：先恢复 MySQL 和上传原件；向量服务不可恢复时，根据保留的源文件重新入库。恢复演练不得覆盖正在使用的生产数据目录。

## 5. 质量验收

业务负责人维护一套未参与开发调参的真实问题集，至少覆盖：直接事实、跨段归纳、同义表达、多轮指代、无答案拒答、过期资料和恶意提示。每次知识库大改后运行：

```powershell
python -m scripts.evaluate_retrieval --cases <独立问题集.json>
```

人工验收同时记录答案是否正确、引用是否真的支持答案、应拒答时是否拒答。负面反馈必须能够追溯到文档版本或检索问题，并在下一轮试点前闭环。

## 6. 并发与容量验收

使用专门的普通员工测试账号执行，密码通过交互输入，不进入命令历史：

```powershell
python -m scripts.pilot_load_test --username pilot.employee --requests 10 --concurrency 3
```

结果写入 `reports/pilot_load_test.json`。逐步增加并发，不要第一次就压满 GPU。记录成功率、P50/P95、GPU 显存、DeepSeek 限流和单次问答 Token。只有连续三轮满足业务 SLA 才扩大用户范围。

## 7. 故障处置

- API 重启：上个进程遗留的问答和入库任务会被标记为“因重启中断”，不会永久显示运行中。用户重新提问，管理员重新上传失败文件。
- DeepSeek 异常：暂停新增用户，保留检索能力检查结果，待上游恢复后再重试。
- Milvus 异常：禁止执行“清空旧知识后重建”，先检查 MySQL 真源和最近备份。
- 磁盘空间不足：停止上传，备份后清理到期数据与旧日志，确认空间恢复再继续。
- 误删文档：暂停继续入库，从最近备份恢复源文件并重新索引，记录事故和受影响时间段。
- 账号疑似泄露：立即停用账号或重置密码；已有会话会被撤销，再审查管理审计记录。

## 8. 扩大试点门槛

- 角色越权测试全部通过。
- 最近一次备份成功且恢复演练通过。
- 独立问题集达到业务方签字确认的正确率和引用准确率。
- 并发压测连续三轮满足 SLA，无卡住任务。
- 外部模型数据策略获得资料所有者确认。
- 至少两名实名管理员，初始共享管理员账号不再用于日常操作。
